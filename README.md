# gRPC_Wallet_Demo

A small iOS banking-app skeleton built to exercise a full, realistic senior-iOS stack end to
end — not tutorials copied in, but a hand-written `.proto` contract, a real modular
architecture, real fintech-level security primitives, and a real local Jenkins pipeline that
was debugged against its actual failures rather than assumed to work.

The scope is deliberately narrow (one balance screen, one benchmark screen) so that the depth
sits in the plumbing, not in UI surface area.

## Structure

- `Proto/wallet.proto` — the gRPC contract, hand-written, not copied from a template.
- `WalletKit/` — a local Swift package with five modules:
  - `WalletContracts` — the code generated by `protoc` from `wallet.proto` (Swift message types
    + gRPC client), kept internal to the package.
  - `WalletNetworking` — the only module allowed to import `WalletContracts`. Maps generated
    types to plain domain models (`Balance`, `Transaction`) so nothing above this layer ever
    sees a generated type. Holds a long-lived `GRPCClient` inside an `actor`, created once and
    reused, protected against duplicate creation by keeping the check-and-store step
    synchronous (no `await` between them).
  - `CoreSecurity` — a `KeychainStore` with proper accessibility flags, and a
    `JailbreakDetector` running independent filesystem/sandbox/URL-scheme checks.
  - `CoreUI` — a tiny design system (colors, a button style).
  - `FeatureAuth` — the only module allowed to depend on more than one Core module at once;
    composes `CoreSecurity` + `WalletNetworking` into a login flow.
- `gRPC_Wallet_Demo/` — the SwiftUI app: a manual DI container (`AppContainer`) as the single
  composition root, a `Coordinator` driving `NavigationStack` so screens never navigate
  themselves, and a `SecureContainerView` that renders sensitive content through a secure
  `UITextField` layer (blank during screen recording/mirroring — a real, honest technique, not
  a screenshot blocker, since iOS has no API to block screenshots).
- `server/` — a local Python server exposing the *same* data over gRPC and plain JSON, used to
  benchmark protobuf against JSON on identical payloads.
- `Jenkinsfile` + `fastlane/Fastfile` — a real local CI pipeline: test → build → release stages,
  the release stage gated to `main` only.

## What's demonstrated

| Topic | Where |
|---|---|
| Hand-written `.proto`, codegen for two languages (Swift + Python) | `Proto/wallet.proto`, `generate.sh` |
| Long-lived gRPC connection, single-flight client creation | `WalletNetworking.swift` — actor, no `await` between check and store |
| gRPC vs JSON — real benchmark, same data, Debug vs Release | `getTransactionsViaGRPC` / `getTransactionsViaJSON` |
| Modular architecture with enforced dependency direction | `WalletKit/Package.swift` — SPM throws a real cyclic-dependency error if the direction is broken |
| Manual DI via a single composition root | `AppContainer.swift` |
| Coordinator pattern on `NavigationStack` | `AppCoordinator.swift` |
| Keychain storage with correct accessibility flags | `CoreSecurity/KeychainStore.swift` |
| Jailbreak detection (filesystem, sandbox write test, forbidden URL scheme) | `CoreSecurity/JailbreakDetector.swift` |
| Screen-recording protection via secure-layer trick | `SecureContainerView.swift` |
| Real local CI/CD — Jenkins + Fastlane, gated release stage | `Jenkinsfile`, `fastlane/Fastfile` |

## Known limitations — stated honestly, not hidden

- **`getBalance` UI binding bug:** the gRPC call succeeds and is logged server-side, but the
  fetched value doesn't always reach the SwiftUI screen. Root cause not yet fully isolated —
  documented here rather than fixed silently, since diagnosing it out loud is more useful than
  pretending it doesn't exist.
- Server-streaming gRPC (`stream GetBalanceResponse`) is designed in the `.proto` comments but
  not yet implemented on either side.
- `fastlane match` is intentionally not wired up — it requires a paid Apple Developer account
  this project doesn't have. The `Jenkinsfile`'s release stage documents where it would go.

## Running it

```bash
# 1. Start the servers (gRPC on 50051, JSON on 50052)
cd server && source venv/bin/activate && python server.py

# 2. Build and run the app
open gRPC_Wallet_Demo.xcodeproj   # or: fastlane ios build_simulator
```
